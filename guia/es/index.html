En resumen

Esta es una guía gratuita para ordenar la configuración de quienes usan Claude Code y Codex. Con el tiempo, se acumulan archivos de instrucciones repetidos, skills descargadas que nunca se usan, memorias antiguas y reglas contradictorias; todo eso entra en el contexto antes de la primera solicitud y el agente empieza a ignorar reglas y a consumir más. La guía muestra una auditoría hecha con un prompt, un script que lee tu historial, un único AGENTS.md, carpetas por negocio, playbooks y un filtro de tres preguntas. Para usarla, solo necesitas tener Claude Code o Codex instalado y Python 3.

Qué es

Por qué tu agente empeora con el tiempo

No es el modelo. Es lo que recibe antes de que escribas la primera palabra.

🗂️ Demasiadas instrucciones

CLAUDE.md, AGENTS.md y GEMINI.md hablando al mismo tiempo, con reglas que se contradicen.

🧰 Skills sin uso

Paquetes instalados por un tutorial y olvidados. Cada uno desvía un poco al agente.

📉 Límite agotado

La memoria antigua, las notas viejas y los archivos temporales ocupan el contexto y el límite se agota antes de terminar el trabajo.

Guía · paso a paso

La limpieza en 6 pasos

Primero clona el repositorio. Los siguientes comandos se ejecutan dentro de esa carpeta.

git clone https://github.com/inematds/faxina-agentes
cd faxina-agentes
1

Auditoría con un prompt

No hace falta un prompt enorme. Indica tres cosas: qué auditar, con qué compararlo y qué criterio usar. El agente solo lee y propone; nada cambia sin tu aprobación.

# el prompt listo para pegar
cat prompts/auditoria.md
2

Un script lee el historial

Leer cientos de conversaciones completas con el agente cuesta caro. El script recorre los archivos de conversación de Claude y Codex, cuenta mensajes con fricción («no fue eso lo que pedí») y enumera las skills que nunca invocaste. Solo lectura, sin API.

python3 scripts/varrer_historico.py --dias 60
# listo: relatorio-faxina.md y relatorio-faxina.html | fricción … | skills nunca usadas …

Empieza por las limpiezas de bajo riesgo: un hook obsoleto, un archivo temporal o una skill sin uso desde hace meses.

3

Un AGENTS.md como torre de control

Lo que se aplica a todas las herramientas queda en un solo AGENTS.md: reglas de escritura, qué significa «terminado» y qué nunca hacer. Codex lee ese archivo directamente; en Claude Code, CLAUDE.md solo apunta a él. Las reglas específicas quedan aparte solo cuando una función existe en una herramienta.

cp modelos/AGENTS-raiz.md ~/trabalho/AGENTS.md
echo '@AGENTS.md' > ~/trabalho/CLAUDE.md
4

Una carpeta por negocio o cliente

Cada línea de negocio y cada cliente tiene su propia carpeta con su AGENTS.md (tono, público y reglas de ese espacio). Solo se carga cuando el agente trabaja allí, así que nada se filtra de un cliente a otro.

mkdir -p ~/trabalho/{conteudo,vendas,clientes/cliente-a}
cp modelos/AGENTS-pasta.md ~/trabalho/clientes/cliente-a/AGENTS.md
5

Playbooks en lugar de otra skill

Lo que sabes hacer de memoria vale más que una skill genérica. Graba una hora explicando el proceso, transcríbelo y pídele al agente que lo organice en archivos como lancamento.md y aula.md. El AGENTS.md principal indica cuándo consultar cada uno.

mkdir -p ~/trabalho/playbooks
cp modelos/playbook-modelo.md ~/trabalho/playbooks/lancamento.md
6

Limpieza programada

El desorden vuelve si nadie limpia. Programa la misma auditoría cada semana (tarea programada de Codex o /schedule en Claude Code), con esta regla: limpiar automáticamente solo lo de bajo riesgo; el resto queda en una lista para que decidas.

# en Claude Code
/schedule todos los lunes a las 8: ejecuta prompts/auditoria.md y limpia solo lo de bajo riesgo
Antes de instalar algo nuevo

El filtro de tres preguntas

Un grado de error en el rumbo de un barco parece insignificante; al final del viaje, puede llegar a más de cien kilómetros del destino. Cada skill fuera de lugar es ese grado.

1

¿Sirve para casi todas las tareas?

Si no, no la instales. Indícale al agente el repositorio y copia solo la línea que importa a tu AGENTS.md.

2

¿Solo es útil a veces?

Entonces va en la carpeta del proyecto que la usa, nunca de forma global. El resto del trabajo no carga con ese peso.

3

¿Quién lo limpia?

La limpieza programada de la semana. Los modelos mejores necesitan menos reglas: quita peso, no acumules.
