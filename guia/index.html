Em resumo

Este é um guia grátis para arrumar o setup de quem usa o Claude Code e o Codex. Com o tempo, juntam-se arquivos de instrução repetidos, skills baixadas e nunca usadas, memórias velhas e regras que se contradizem; tudo isso entra no contexto antes do primeiro pedido e o agente passa a ignorar regras e gastar mais. O guia mostra uma auditoria feita com um prompt, um script que lê o seu histórico, um AGENTS.md único, pastas por negócio, playbooks e um filtro de três perguntas. Para usar, basta ter o Claude Code ou o Codex instalado e Python 3.

O que é

Por que o seu agente piora com o tempo

Não é o modelo. É o que ele recebe antes de você digitar a primeira palavra.

🗂️ Ordens demais

CLAUDE.md, AGENTS.md e GEMINI.md falando ao mesmo tempo, com regras que não batem entre si.

🧰 Skills paradas

Pacotes instalados por causa de um tutorial e esquecidos. Cada um empurra o agente um pouco para o lado errado.

📉 Limite queimado

Memória velha, notas antigas e arquivos temporários ocupam o contexto e o limite acaba antes do trabalho.

Guia · passo a passo

A faxina em 6 passos

Primeiro clone o repositório. Os comandos abaixo rodam dentro da pasta dele.

git clone https://github.com/inematds/faxina-agentes
cd faxina-agentes
1

Auditoria com um prompt

Não precisa de um prompt gigante. Diga três coisas: o que auditar, contra o quê e com que critério. O agente só lê e propõe; nada muda sem o seu OK.

# o prompt pronto para colar
cat prompts/auditoria.md
2

Um script lê o histórico

Ler centenas de conversas inteiras com o agente custa caro. O script varre os arquivos de conversa do Claude e do Codex, conta mensagens com atrito ("não foi isso que eu pedi") e lista as skills que você nunca chamou. Só leitura, sem API.

python3 scripts/varrer_historico.py --dias 60
# ok: relatorio-faxina.md e relatorio-faxina.html | atrito … | skills nunca usadas …

Comece pelas limpezas de baixo risco: hook morto, arquivo temporário, skill parada há meses.

3

Um AGENTS.md como torre de controle

O que vale para todas as ferramentas fica num AGENTS.md só: regras de escrita, o que é "pronto", o que nunca fazer. O Codex lê esse arquivo direto; no Claude Code, o CLAUDE.md só aponta para ele. Regra específica fica separada só quando o recurso existe numa ferramenta.

cp modelos/AGENTS-raiz.md ~/trabalho/AGENTS.md
echo '@AGENTS.md' > ~/trabalho/CLAUDE.md
4

Uma pasta por negócio ou cliente

Cada linha de negócio e cada cliente ganha uma pasta com o seu próprio AGENTS.md (tom, público, regras daquele lugar). Ele só entra quando o agente trabalha ali dentro, então nada vaza de um cliente para o outro.

mkdir -p ~/trabalho/{conteudo,vendas,clientes/cliente-a}
cp modelos/AGENTS-pasta.md ~/trabalho/clientes/cliente-a/AGENTS.md
5

Playbooks no lugar de mais uma skill

O que você sabe fazer de cabeça vale mais que uma skill genérica. Grave uma hora explicando o processo, transcreva e peça ao agente para organizar em arquivos como lancamento.md e aula.md. O AGENTS.md de cima diz quando consultar cada um.

mkdir -p ~/trabalho/playbooks
cp modelos/playbook-modelo.md ~/trabalho/playbooks/lancamento.md
6

Faxina agendada

A bagunça volta se ninguém limpa. Agende a mesma auditoria toda semana (tarefa agendada do Codex ou /schedule no Claude Code), com a regra: limpar sozinho só o que é de baixo risco; o resto vira lista para você decidir.

# no Claude Code
/schedule toda segunda 8h: rode prompts/auditoria.md e limpe só o baixo risco
Antes de instalar qualquer novidade

O filtro de três perguntas

Um grau de erro na saída de um barco parece nada; no fim da viagem, ele chega a mais de cem quilômetros do destino. Cada skill fora do lugar é esse grau.

1

Serve para quase toda tarefa?

Se não serve, não instale. Aponte o agente para o repositório e copie só a linha que importa para o seu AGENTS.md.

2

É útil só às vezes?

Então fica na pasta do projeto que usa, nunca global. O resto do trabalho não carrega esse peso.

3

Quem limpa?

A faxina agendada da semana. Modelos melhores precisam de menos regras: tire peso, não acumule.
